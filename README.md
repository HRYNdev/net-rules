# NetRules

Списки маршрутизации для домашней сети: что идёт через туннель, что напрямую.

Правится один файл, дальше расходится само — и на роутер, и на клиенты. Перезапускать ничего не нужно.

## Зачем так

Раньше списки жили одной строкой в конфиге роутера. Любое добавление домена означало перезапуск, а перезапуск рвёт связь всему дому. Плюс устройства вне дома этих правил не видели вообще.

Теперь: правка в `src/` → сборка → релиз `latest` → потребители сами забирают обновление по расписанию, без разрывов.

## Что внутри

| Файл | Что это |
|---|---|
| `src/main-domains.lst` | домены, которые идут через туннель |
| `src/main-subnets.lst` | подсети, которые идут через туннель (для трафика, где имя не видно) |

Один домен или подсеть на строку. Строки, начинающиеся с `#`, игнорируются.

Домены сопоставляются как суффиксы: `example.com` покрывает и `api.example.com`, и `cdn.example.com`.

## Как добавить домен

```powershell
.\add-domain.ps1 example.com cdn.example.com
```

Одна команда делает всё и занимает около полуминуты:

| Когда | Что происходит |
|---|---|
| сразу | домен попадает в срочный набор роутера, sing-box перечитывает правила **без перезапуска** — дома всё работает через секунды |
| ~15 с | домен уходит в репозиторий, конвейер пересобирает набор |
| ~30 с | раздача на сервере забирает свежий набор |
| дальше | устройства вне дома подхватывают при очередном обновлении |

В конце команда сама проверяет, что домен реально попал в набор на раздаче и работает на роутере.

Раз в два часа роутер убирает из срочного набора те домены, которые уже приехали в основной — чтобы срочный оставался маленьким и содержал только то, что ещё в пути.

**Важно про CDN.** Один домен сервиса обычно не работает: картинки, видео и API живут на отдельных адресах. Так было с mangalib (основной домен в списке, а картинки нет) и со Spotify (сам сервис заворачивался, а музыка шла мимо). Добавляя сервис, проверяй, куда реально ходит приложение.

Проверить, покрыт ли домен уже сейчас:
```
nslookup example.com 127.0.0.1
```
Ответ из диапазона `198.18.x.x` значит домен заворачивается — своим списком или готовым набором сообщества, неважно.

## Правки руками

Если нужно добавить много домов разом, можно править `src/*.lst` напрямую и коммитить. Тогда домены доедут обычным путём, без мгновенного эффекта на роутере.

## Чего здесь нет

Личные домены и адреса собственной инфраструктуры остаются в локальном конфиге роутера и в этот репозиторий не выносятся.

Готовые наборы по подсетям крупных хостеров (Hetzner, OVH, DigitalOcean, Cloudfront, Meta, Telegram) не дублируются — они подключаются напрямую от [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains), который обновляется каждые несколько дней.
