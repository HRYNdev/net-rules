# NetRules

Списки маршрутизации для домашней сети: что идёт через туннель, что напрямую.

Правится один файл, дальше расходится само — и на роутер, и на клиенты. Перезапускать ничего не нужно.

## Зачем так

Раньше списки жили одной строкой в конфиге роутера. Любое добавление домена означало перезапуск, а перезапуск рвёт связь всему дому. Плюс устройства вне дома этих правил не видели вообще.

Теперь: правка в `src/` → сборка → релиз `latest` → потребители сами забирают обновление по расписанию, без разрывов.

## Что внутри

| Файл | Что это |
|---|---|
| `src/main-domains.lst` | домены, которые идут через туннель |
| `src/main-subnets.lst` | подсети, которые идут через туннель (для трафика, где имя не видно) |

Один домен или подсеть на строку. Строки, начинающиеся с `#`, игнорируются.

Домены сопоставляются как суффиксы: `example.com` покрывает и `api.example.com`, и `cdn.example.com`.

## Как добавить домен

1. Дописать строку в нужный файл в `src/`
2. Закоммитить
3. Через несколько минут набор пересобран, потребители подхватят его сами

## Чего здесь нет

Личные домены и адреса собственной инфраструктуры остаются в локальном конфиге роутера и в этот репозиторий не выносятся.

Готовые наборы по подсетям крупных хостеров (Hetzner, OVH, DigitalOcean, Cloudfront, Meta, Telegram) не дублируются — они подключаются напрямую от [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains), который обновляется каждые несколько дней.
